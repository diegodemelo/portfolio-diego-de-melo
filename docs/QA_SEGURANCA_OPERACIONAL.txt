1. OBJETIVO

Validar se metadados internos do repositório Git utilizado no servidor
estavam acessíveis pela publicação HTTP/HTTPS do portfólio.

2. DEFEITO IDENTIFICADO

Foi confirmado acesso público indevido a:

/portfolio/.git/HEAD

Evidência inicial:

HTTP 200
Content-Type: application/octet-stream

Classificação:

DEFEITO REAL DE SEGURANÇA OPERACIONAL

A aplicação permaneceu funcional. O defeito estava restrito à
configuração de exposição de arquivos pelo Nginx.

3. CAUSA TÉCNICA

O projeto é servido através de:

location ^~ /portfolio/ {
    alias /srv/apps/portfolio-diego-de-melo/;
    index index.html;
}

Como o repositório Git local existe dentro desse diretório, o alias
também permitia alcançar arquivos internos de .git.

Os bloqueios existentes para .gitignore, README.md e docs/ não
protegiam o diretório .git/.

4. BACKUP

Configuração:

/etc/nginx/sites-available/rotapotiguar

Backup realizado antes da alteração:

/srv/backups/nginx-pre-git-hardening-20260902-213552.conf

SHA-256 da configuração antes da alteração:

131efe6fe1df97be516418b516eca2a25b7d469025989e2f4f3b521e02a2a14c

O backup foi comparado com o arquivo original e confirmado como
idêntico antes da alteração.

5. CORREÇÃO APLICADA

Foram adicionados os seguintes bloqueios antes do alias principal
do portfólio:

location = /portfolio/.git {
    return 404;
}

location ^~ /portfolio/.git/ {
    return 404;
}

A alteração foi limitada à configuração Nginx do portfólio.
